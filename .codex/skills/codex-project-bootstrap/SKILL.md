# Codex 项目初始化

为项目建立 Agent 可立即执行的仓库规则和可持续维护的文档入口。只写入从仓库或用户确认得到的事实，不用通用模板臆造项目命令、技术栈或目录。

## 初始化流程

1. 检查仓库根目录、已有 `AGENTS.md`、嵌套指令、README、代码与测试目录、构建清单、配置和文档。已有内容必须合并理解，不得直接覆盖。
2. 区分已确认事实、可从仓库证明的事实和需要用户确认的事项。技术栈、运行命令、发布方式、受限目录或协作习惯不明确时先提出问题。
3. 如果存在会阻塞初始化或决定技术路线的未知项，读取 [references/initialization-questions.md](references/initialization-questions.md)，只生成当前轮次的一小组问题；不要一次罗列所有未知项。
4. 选择指令范围：跨仓库规则写入根 `AGENTS.md`；只有子目录需要不同规则时才创建嵌套 `AGENTS.md`。
5. 使用 [assets/AGENTS.md.template](assets/AGENTS.md.template) 形成项目版本。替换所有占位符，删除不适用章节，并保持内容简洁。
6. 根据 [references/documentation-structure.md](references/documentation-structure.md) 确定文档所有权。先创建当前需要的最小目录和导航，不为尚不存在的流程生成大量空目录。
7. 在 `AGENTS.md` 中记录生命周期路由、真实命令、代码质量、Git 工作流、验证要求、路径隐私和文档导航；长背景、设计或决策放入对应 `docs/`。
8. 检查所有文件链接、示例和命令只使用仓库相对路径。扫描并移除盘符、用户目录、本机地址、密钥和其他环境身份信息。
9. 向用户说明创建或更新了哪些规则、哪些事实仍待确认，以及下一步应进入哪个生命周期阶段。

## 编写规则

- `AGENTS.md` 只保留稳定、高频、执行期必须立即看到的规则，不充当完整知识库。
- 不写无法从代码、配置或用户回答确认的命令、端口、目录职责和交付方式。
- 不因模板存在某一章节就强制项目采用该流程；删除不适用内容。
- 不覆盖用户已有规则；存在冲突时列出差异并请求决定。
- 不在多个位置维护同一事实；`AGENTS.md` 负责规则和导航，详细内容放在唯一的 system of record。
- 所有可提交内容使用仓库相对路径，不记录本机绝对路径或真实环境身份。
- 初始化提问默认使用选择题，不把多个主题的未知项合并成一份长问卷。
- 每轮只处理一个主题，通常提出 1-3 个当前最关键的问题；用户回答后更新原问题文档，再决定是否进入下一轮。
- 每个选择题提供 2-4 个有实际差异的选项，并在末尾提供 `其他，请说明：` 或 `暂不确定，请先给出建议：`。选项必须来自证据或明确标为建议，不得把 Agent 的猜测写成项目事实。
- 问题文档必须有合法的类型化编号、日期、状态、背景、已知证据、问题、回答区和确认后的处理；生成后检查标题、编号和 Markdown 结构，清除类似 `问题UN.` 的残留占位文本。

## 最小交付

项目初始化至少交付：

- 根 `AGENTS.md`
- 文档所有权和导航位置
- 已确认的开发、验证和沟通规则
- 生命周期 Skill 的自然语言路由规则
- 已确认的代码质量和 Git 协作规则
- 尚未确认事项及其回答位置

初始化完成后，模糊想法进入 `$software-delivery`；已有明确任务则使用 `$software-development-lifecycle` 判断当前阶段。
