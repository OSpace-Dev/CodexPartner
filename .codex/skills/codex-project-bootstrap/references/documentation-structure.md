# 通用项目文档结构

这是没有项目专用约定时的建议起点。使用前先检查仓库 `AGENTS.md`；已有 system of record 时，不要另建重复目录。

```text
docs/
├─ README.md                 # 文档导航和所有权说明
├─ requirements/             # 已确认的需求简报
├─ questions/                # 需要用户或负责人确认的问题
├─ architecture/             # 架构、概要设计和详细设计
├─ api/                      # API、事件和跨边界契约
├─ ui/                       # 用户流程、页面和界面设计规格
├─ planning/                 # Roadmap、Milestone、Backlog 和任务入口
├─ reviews/                  # 只读评审报告和复审记录
├─ testing/                  # 测试方案、人工协议和测试报告
├─ deployments/              # 部署计划、执行记录和回退记录
├─ operations/               # 运行手册、维护和恢复记录
├─ decisions/                # 已确认的架构、产品和流程决策
├─ standards/                # 稳定、可复用的项目规范
├─ version-control/          # 重要远端、迁移和历史操作记录
├─ investigations/           # 排障、实验和证据记录
└─ templates/                # 需求、问题、决策和排障文档模板
```

## 所有权规则

- 一个主题只保留一个 system of record；其他位置只做链接或导航。
- 只影响单个子项目的文档放在该子项目的文档范围内；影响多个项目的内容放在共享范围。
- `questions/` 记录尚未确认的内容；回答完成后保留决策历史，并链接到最终需求或决策文档。
- `requirements/` 只记录已经足以进入规划的范围，不把开放问题伪装成已确认需求。
- `decisions/` 只记录已经作出的选择，包含背景、备选方案、结论和后果。
- `investigations/` 记录证据链，不用聊天记录代替问题现象、根因和修复依据。

## 文件命名与编号

默认使用 `YYYY-MM-DD-NNN-topic.md`，例如 `2026-08-08-001-login-scope.md`。`NNN` 是当天在当前文档类别中的三位顺序号，从 `001` 开始；同一天新增多份文档时依次递增。

需要跨目录引用和状态追踪时，同时在文档内设置类型化编号：

| 文档类型 | 编号示例 |
| --- | --- |
| 需求 | `REQ-20260808-001` |
| 问题 | `Q-20260808-001` |
| 架构设计 | `ARCH-20260808-001` |
| 概要设计 | `HLD-20260808-001` |
| 详细设计 | `LLD-20260808-001` |
| API 契约 | `API-20260808-001` |
| 界面设计 | `UI-20260808-001` |
| 里程碑 | `MS-20260808-001` |
| 任务 | `TASK-20260808-001` |
| 评审报告 | `REV-20260808-001` |
| 测试方案或报告 | `TEST-20260808-001` |
| 测试用例 | `TC-20260808-001` |
| 部署记录 | `DEP-20260808-001` |
| 运维记录 | `OPS-20260808-001` |
| 编码规范 | `STD-20260808-001` |
| Git 操作记录 | `GIT-20260808-001` |
| 决策 | `DEC-20260808-001` |
| 排障记录 | `INV-20260808-001` |

- 编号一经分配不得因排序、移动目录或标题变化而修改。
- 同一类别每天独立编号；创建前检查目标目录，使用下一个未占用编号。
- 文件名中的主题使用简短、稳定、可检索的英文；正文标题和内容可以使用中文。
- 一个文件只聚焦一个主题，避免持续追加成无法检索的总文档。

## 路径与环境隐私

- 所有准备保存在项目中的文档、模板、代码注释、示例命令和配置，只能使用仓库相对路径。
- Markdown 链接使用相对于当前文档的链接，或使用项目明确规定的仓库相对链接；不得使用盘符、用户目录、工作区上级目录、本地文件 URI、IDE 专用 URI 或其他本机绝对地址。
- 从仓库根目录执行的命令直接写命令；需要进入子目录时使用仓库相对路径。
- 运行时必须使用绝对路径时，通过环境变量、命令行参数或 Git 忽略的本地配置传入，不得写入可提交文档和配置。
- 输出文档前扫描绝对路径和本机身份信息；发现后改写为相对路径、变量或通用占位符。
- 文档中的外部公开 URL 不属于本机路径，可以在确有需要时保留。
