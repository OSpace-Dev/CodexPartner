# 代码质量参考

## 实现检查

- [ ] 名称能说明领域含义、职责和单位。
- [ ] 模块边界和依赖方向清楚，没有新增不必要耦合。
- [ ] 正常、错误和边界路径可以理解并验证。
- [ ] 状态所有权、资源生命周期和副作用明确。
- [ ] 重复与抽象的取舍基于真实变化原因。
- [ ] 没有为当前任务引入无用扩展点或通用框架。
- [ ] 注释、类型、日志和代码行为一致。
- [ ] 测试关注可观察行为，而不是脆弱的内部步骤。

## 坏味道记录模板

```md
## [问题标题]

- 位置：[仓库相对路径和行号]
- 现象：[具体代码结构]
- 影响：[正确性、理解、修改、测试或运行风险]
- 证据：[当前任务或历史变化如何触发问题]
- 建议边界：[最小改善范围]
- 不处理的代价：[说明]
```
