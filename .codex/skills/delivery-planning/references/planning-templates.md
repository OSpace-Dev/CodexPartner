# 交付规划参考

## 层次选择

| 情况 | 建议产物 |
| --- | --- |
| 单一边界、低风险、可快速验证 | 一个任务 |
| 多步实施、存在依赖或需要阶段性验收 | 一个里程碑和多个任务 |
| 多个独立成果、跨项目或长期方向 | Roadmap、里程碑和任务 |

不要因为使用某种项目管理工具就机械创建所有层次。选择最小但足够表达依赖、验收和交付顺序的层次。

## Roadmap 模板

```md
# [方向或项目组合]

编号：ROADMAP-[YYYYMMDD]-[NNN]

## 目标

[在何时为谁创造何种可观察价值。]

## 非目标

- [明确不纳入的范围]

## 里程碑

1. [里程碑名称]：[可观察交付结果]；目标时间：[时间或条件]
2. [里程碑名称]：[可观察交付结果]；目标时间：[时间或条件]

## 主要风险与依赖

- [风险、依赖、负责人或下一决策]
```

## 里程碑模板

```md
# [里程碑名称]

编号：MS-[YYYYMMDD]-[NNN]

## 交付结果

[完成后用户、调用方或运维方能够观察到什么。]

## 验收条件

1. [可观察条件]
2. [可观察条件]

## 范围与依赖

- 范围：[包含的能力或边界]
- 非目标：[不包含的内容]
- 前置依赖：[任务、决策、外部系统或无]
- 主要风险：[风险及缓解方式]

## 任务

1. [任务名称]
2. [任务名称]
```

## 任务模板

```md
# [任务名称]

编号：TASK-[YYYYMMDD]-[NNN]

## 目标

[任务完成后可验证的结果。]

## 范围

- 包含：[行为、组件或边界]
- 不包含：[明确排除的工作]

## 前置条件与依赖

- [已完成任务、待决策事项、外部输入或无]

## 完成定义

1. [实现或行为条件]
2. [测试、构建、类型检查或人工验收条件]
3. [需要同步的文档、任务状态或决策记录]

## 验证

- 自动化：[命令或测试范围]
- 人工：[场景、环境和观察点]

## 风险与回退

- [风险、监控、兼容性或回退方案；无则明确写无]
```

## 拆分检查

每个任务开始前确认：

1. 不依赖隐含的产品或架构决策。
2. 不包含多个彼此独立的可交付结果。
3. 能用明确方式验证完成或失败。
4. 能说明依赖关系和受影响边界。
5. 不会因机会性工作扩大原定范围。

## 文件命名

- Roadmap、里程碑和任务文档使用 `YYYY-MM-DD-NNN-topic.md`。
- `NNN` 是当天在当前文档类别中的三位顺序号，从 `001` 开始。
- 创建前检查目标目录，使用下一个未占用编号；编号分配后不因移动或改名而重排。
- 文件名主题使用简短、可检索的英文，正文使用项目约定的主要语言。
