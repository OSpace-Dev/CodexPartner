# 技术域路由

## 何时使用专项 Skill

出现以下任一情况时，应加载现有专项 Skill；不存在时，考虑在重复出现后建立新的专项 Skill：

- 需要特定框架、平台、协议或工具链的非通用知识。
- 错误会导致数据损坏、安全问题、设备不可恢复或生产事故。
- 同类任务反复需要相同的命令、检查清单、模板或环境准备。
- 通用最佳实践与当前技术域存在明显例外。

专项 Skill 应补充通用实施流程，不复制需求澄清、任务准入、范围控制和收口规则。

## 建议的专项边界

| 技术域 | 可沉淀内容 | 不应重复内容 |
| --- | --- | --- |
| 前端 | 框架约定、状态模型、设计系统、浏览器与视觉验证 | 通用任务准入和收口 |
| 后端 | API、鉴权、事务、消息、数据库和可观察性 | 通用范围控制 |
| 系统软件 | 内存、并发、ABI、性能分析和平台构建 | 通用需求流程 |
| 嵌入式 | 芯片与板卡、工具链、时序、刷写、设备测试和恢复 | 通用任务模板 |
| 数据迁移 | 模式演进、批次、校验、回滚和生产操作 | 通用完成定义 |

## 冲突处理

仓库专用约束优先于通用 Skill。专项 Skill 与仓库事实不一致时，以仓库内有效的版本、配置、测试和决策记录为依据，并记录需要修订的 Skill 规则。
