# 本地打包、远端 Docker 构建

## 适用条件

适用于个人或小型后端项目，目标服务器具备 Linux、SSH、足够磁盘空间，以及可用的 Docker Engine 和 Compose 插件。服务器需要能够访问构建所需的镜像仓库或依赖源。

不适用于必须由受控 CI 生成可证明制品、服务器禁止构建、构建资源不足，或合规要求禁止上传源码的环境。

## 推荐流水线

```text
本地预检
  -> 从明确文件清单创建源码包
  -> 生成发布清单和 SHA-256
  -> 上传临时目录
  -> 服务器校验 SHA-256
  -> 解压到 releases/<release-id>
  -> 服务器构建唯一标签镜像
  -> 注入服务器端配置并启动
  -> 健康检查和人工验收
  -> 记录部署或回退
```

## 打包规则

- 优先从 Git 已跟踪文件或项目维护的显式清单生成压缩包，避免直接压缩整个工作区。
- 必须包含 Dockerfile、锁文件、Compose 配置、构建脚本、必要源码、静态资源和受控迁移文件。
- 必须排除 `.git/`、依赖缓存、构建缓存、日志、临时文件、测试证据、编辑器目录、私钥、`.env` 和机器专用配置。
- 对必须包含但未被 Git 跟踪的资源使用显式允许列表，并记录来源和校验值。
- 发布包使用唯一名称，例如 `<app>-<version>-<revision>.tar.gz`，同时生成清单和 SHA-256 文件。

## 服务器目录

采用不可变发布目录，不直接覆盖当前版本：

```text
<deploy-root>/
├─ releases/<release-id>/
├─ shared/                  # 服务器端配置、持久数据或挂载目录
├─ artifacts/               # 上传的压缩包和校验文件
└─ current                  # 当前版本指针或等价映射
```

路径由项目配置明确给出；部署脚本必须验证最终路径位于允许的部署根目录内。

## 构建与启动

- 使用锁文件和明确基础镜像版本确保构建可重复；重要环境可进一步固定镜像 digest。
- 镜像标签包含发布标识，不复用模糊的 `latest` 作为唯一回退依据。
- 密钥和运行时配置保存在服务器 `shared/`、环境管理或密钥服务中，不进入压缩包和镜像层。
- 数据迁移作为显式步骤执行，记录备份、兼容性、执行结果和失败处理；不要无条件绑定到每次容器启动。
- 新容器通过健康检查后才切换流量或停止旧版本；环境不支持并行版本时，明确停机窗口。

## 回退与保留

- 至少保留上一个已验证的发布目录、镜像标签和匹配配置。
- 应用回退与数据回退分开设计；不可逆迁移优先使用兼容前滚方案。
- 按数量和时间配置旧版本保留策略，仅在新版本验证成功后清理。

## 一键入口配置

项目的一键命令应从受控配置读取应用名、目标主机、部署根目录、Compose 项目名、健康检查地址、保留数量和超时。密钥使用 SSH Agent、环境注入或密钥管理工具，不写入命令参数、仓库配置或部署日志。
