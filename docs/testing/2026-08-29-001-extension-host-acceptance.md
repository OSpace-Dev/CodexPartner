# Extension Host 人工验收协议

测试编号：`TEST-20260829-001`

## 目的

验证 VS Code 扩展开发宿主中的 Codex Partner 是否能够通过本机 Codex App Server 浏览会话、读取历史、创建线程并接收流式回复。

## 前置条件

- 已安装 VS Code 和官方 Codex 扩展。
- 当前 Codex CLI 已完成登录，且目标工作区已被 Codex 配置为 trusted project。
- 当前工作区打开的是本仓库根目录。
- 已运行 `npm run check`，自动化检查通过。

## 操作步骤与预期

1. 在 VS Code 中打开本仓库根目录，按 `F5`，选择 `Run Codex Partner`。
   预期：打开独立的 Extension Development Host；后续验收操作都在新窗口中进行，扩展宿主无激活错误。
2. 在 Extension Development Host 中点击活动栏中的 `Codex Partner`，打开 `Codex` 视图。
   预期：视图显示会话选择器、消息区域和输入框。
3. 等待初始加载完成。
   预期：会话选择器出现当前 Codex CLI 可见的线程；若没有线程，显示空列表状态而不是崩溃。
4. 选择一个已有线程。
   预期：消息区域显示该线程的用户消息和 Codex 消息，切换期间有加载状态。
5. 点击新建线程按钮。
   预期：出现新的选中线程，历史区域清空，其他线程仍保留在选择器中。
6. 输入一个不需要工具调用的纯文本问题并发送。
   预期：输入框内容提交后显示用户消息；Codex 回复以增量形式显示，完成后状态恢复为 `Ready`，线程列表更新时间刷新。
7. 在编辑器中选择一段跨 2 至 3 行的文本，观察选区旁的灯泡，或按 `Ctrl+.` 打开 Code Action 菜单，选择“添加到 Codex Partner 对话”。
   预期：VS Code 原生 Code Action 菜单显示该操作；Codex Partner 视图被打开或显示；引用以工作区相对文件路径和 1-based 行号范围插入输入框；原有输入内容保留，光标位于引用末尾。
8. 将光标移动到输入框中间，再重复添加另一段选区。
   预期：新引用插入当前光标位置，不覆盖光标前后的既有文本。
9. 关闭或终止 Codex CLI 后点击刷新，再恢复 CLI 并再次点击刷新。
   预期：异常状态显示可诊断错误；恢复后能够重新建立连接，不需要重启 VS Code。

## 通过标准

- 步骤 1 至 5 无扩展宿主异常。
- 至少一个已有线程可以读取历史。
- 新线程可以创建并保持选中。
- 步骤 6 能观察到用户消息、增量回复和完成状态。
- 步骤 7 至 8 能准确插入文件路径和行号引用。
- 选中文本时能通过灯泡或 `Ctrl+.` 看到“添加到 Codex Partner 对话”。
- 连接失败后没有永久停留在失效 client 状态。
