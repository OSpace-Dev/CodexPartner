# 扩展原型代码评审

编号：`REV-20260829-001`

## 发现

### REV-20260829-001-F001 [P2] 请求写入失败会遗留 pending 定时器

- 位置：`src/app-server-client.js` 的 `request()`
- 触发：App Server 已退出，或 stdin 在设置 pending 状态后变为不可写。
- 现状：`write()` 同步抛错会使 Promise 失败，但 pending Map 项和 timeout 没有清理。
- 影响：短期表现为重复的超时错误，长期可能保留无效定时器和请求状态。
- 修复方向：捕获写入异常，删除对应请求并清理定时器后再 reject。
- 状态：已解决。写入异常现在会清理对应请求和定时器后再 reject。

### REV-20260829-001-F002 [P2] 首次发送消息时用户消息会被清空

- 位置：`extension.js` 的 `send()` 与 `newThread()`
- 触发：当前没有选中线程时直接在输入框发送第一条消息。
- 现状：`send()` 先加入用户消息，随后 `newThread()` 将 history 重置为空。
- 影响：界面中不会显示这条用户消息；发送仍可能继续执行，造成对话上下文显示不完整。
- 修复方向：在没有线程时先创建线程，再追加用户消息并启动 turn。
- 状态：已解决。`send()` 现在先确保线程存在，再追加用户消息。

## 结论

通过。两个 P2 问题已修复；其余范围与当前原型目标一致。
