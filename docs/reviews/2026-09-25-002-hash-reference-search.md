# 井号引用搜索评审

编号：REV-20260925-002

评审对象：内容记录面板中输入 `#` 触发工作区文件/目录搜索并插入引用气泡的交互。

需求依据：[本地内容记录面板](../requirements/2026-09-13-001-prompt-notes.md) 的 UI-20260925-002。

## 结论

实现符合当前范围：宿主侧复用工作区索引，Webview 在触发光标上方显示固定高度的搜索浮层，焦点留在富文本编辑器；`#` 后的草稿输入模糊过滤候选，上下方向键循环选择并滚动候选，回车可确认，选择后发送完整本地化引用字符串并由现有富文本解析器渲染为气泡。

## 检查项

- 工作区扫描逻辑抽到共享模块，既服务原有 Quick Pick，也服务面板搜索。
- 索引在面板生命周期内缓存，字符过滤在纯函数中完成并限制返回数量。
- 搜索结果只返回工作区相对路径、类型和引用文本，不暴露本机绝对路径。
- 搜索浮层仅包含 `role=listbox` 的结果列表；编辑器通过 `aria-controls`、`aria-activedescendant` 关联候选，候选使用 `role=option`、选中状态和键盘操作。
- 触发文本只在光标前是独立的 `#query` 时生效，普通文本和既有气泡不被改写。

## 未检查内容

- 尚未在真实 VS Code Extension Host 中检查浮层与光标上方的像素定位、固定高度下的滚动容器边界、主题对比度和极窄侧栏布局。
- 未使用浏览器 DOM 测试环境覆盖真实 Range、contenteditable 光标和鼠标点击候选后的焦点保留。

## 残余风险

- 工作区索引仍受 `findFiles` 的 50,000 文件上限影响；超出上限的文件不会出现在候选中。
- 工作区创建、删除和重命名事件现在会失效索引并通知已打开的菜单重新查询；真实 Extension Host 的事件时序仍待人工验收。
- 搜索候选仍受 `findFiles` 返回结果和工作区索引缓存生命周期约束；复杂筛选条件不改变现有引用格式。
