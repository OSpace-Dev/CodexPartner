# Codex Partner 产品路线图

编号：`ROADMAP-20260829-001`

## 产品定位

Codex Partner 是一个运行在 VS Code 内的本地 Codex 工作台。它复用本机 Codex App Server 的会话和执行能力，并提供 Codex 官方插件和 Codex App 当前没有重点覆盖的入口：将项目中的任意文本、文件片段和编辑器上下文快速加入每次对话。

核心价值不是复制一个聊天窗口，而是让用户能够在代码、文档、配置、诊断信息和其他项目文本之间自然取上下文，再交给 Codex 处理。

## 当前基线

已完成的原型能力：

- 通过本地 `codex app-server --listen stdio://` 读取和发送消息。
- 展示线程列表，读取线程历史，创建线程并接收流式回复。
- 编辑器选区通过 Code Action 或右键命令插入工作区相对文件路径和行号引用。
- 侧边栏未就绪时暂存待插入内容。
- 本地 Node.js 检查和 App Server 客户端测试可运行。

当前版本是开发态原型，不是可发布的 VS Code 扩展包。

## 产品目标

- 让任意项目文本都能成为明确、可管理、可追溯的对话上下文。
- 让用户在一个 VS Code 工作区内完成会话选择、对话、上下文管理和 Codex 操作批准。
- 逐步复刻 Codex 的主要工作流，但保持本项目的核心差异：上下文入口更贴近编辑器和项目。
- 保持本地认证边界：不读取桌面应用 Cookie、Token 或私有数据库。

## 非目标

- 不复制 Codex 桌面应用的私有实现或私有数据格式。
- 不在扩展层保存或解析 ChatGPT 登录凭据。
- 第一阶段不做远程协作、多用户服务、云端代理或跨工作区同步。
- 第一阶段不追求完整复刻 Codex App 的全部视觉细节。

## 里程碑总览

1. **M0 原型基线（已完成）**：能连接本地 App Server，读取和发送线程消息，并从编辑器插入文件行号引用。
2. **M1 上下文引入 v1（已完成）**：已交付编辑器选区的 `fileRange` 上下文项，并可在 Composer 输入框的任意光标位置以内嵌气泡形式插入、编辑和删除。
3. **M2 Session 与会话记录**：区分会话容器和消息/事件时间线，支持稳定浏览、刷新和加载状态。
4. **M3 Markdown 消息展示**：安全渲染 Markdown、代码块、列表、表格、链接和基础格式。
5. **M4 模型与推理设置**：支持模型选择、推理强度等参数，并明确默认值、作用范围和协议兼容性。
6. **M5 审批 UI**：展示 Codex 的命令、文件和其他操作请求，支持逐次批准、拒绝和必要的持久化选择。
7. **M6 Agent 工作流可视化**：展示工具调用、命令输出、文件修改、执行状态，并支持中断和继续对话。
8. **M7 上下文扩展与产品化**：支持更多项目来源、上下文治理、可靠性、可访问性和 VSIX 验收发布。

后续里程碑不默认承诺具体时间，以前一里程碑验收完成和关键协议探针通过作为启动条件。

## M1 上下文引入 v1

### 交付结果

用户可以从 VS Code 项目中选择或提取文本，将其作为当前消息的上下文项以内嵌气泡形式加入 Composer 的任意光标位置；发送前能看到上下文来源，Codex 能收到稳定、可解释的上下文表达。

### 推荐上下文模型

统一抽象为 `ContextItem`，初期至少支持：

- `fileRange`：工作区相对路径、起止行号，可选选区摘要。
- `text`：来自终端、搜索结果、诊断或其他非文件来源的文本。
- `file`：用户明确选择的文件引用，后续再决定是否支持全文预览或按需读取。

当前 M1 优先使用已保存文件的路径和行号引用；未保存文件、外部文本和内嵌文本将作为后续上下文扩展处理。

### 任务

1. 将当前纯文本插入改造成可识别的上下文项序列。
2. 支持编辑器选区的文件行号引用，并保留内嵌选中文本的可选模式。
3. 增加从文件资源管理器、当前文件和终端文本添加上下文的入口评估。
4. 在 Composer 中显示上下文来源、行号、删除操作和过期/不可读取状态。
5. 为 turn 请求定义统一的上下文序列化格式，并保留兼容纯文本消息的回退路径。

### 验收条件

- 选区可通过灯泡入口加入当前 Composer 的最近一次光标位置，且不会丢失原有输入内容。
- 至少两个上下文气泡可以同时存在，并可单独删除，文字可继续在气泡前后编辑。
- 文件路径和行号使用工作区相对路径，不写入本机绝对路径。
- 本 M1 以已保存文件选区的 `fileRange` 引用为通过范围；未保存文本和非文件文本的内嵌发送列入后续上下文扩展。
- 发送前能区分用户指令和上下文项；协议失败时能显示可诊断错误。

### 主要风险

- App Server 对输入内容类型、文件引用和上下文长度的支持需要通过协议探针确认。
- 仅发送文件行号不保证 Codex 在所有执行权限下都能读取文件，因此必须保留内嵌文本回退。
- 大段文本可能造成 token 成本和响应延迟增加，需要在 UI 中显示长度或截断状态。

## M2 Session 与会话记录

### 交付结果

用户能清楚地区分“会话列表”和“当前会话内的消息记录”，并能在两者之间稳定切换。

### 设计边界

- Session/Thread：标题、更新时间、工作区、状态、当前选中项。
- 会话记录：用户消息、Codex 回复、工具事件、审批事件和错误事件。
- 记录顺序以服务端事件和 turn/item 标识为准，不依赖 Webview 临时顺序。

### 任务与验收

- 将当前单一历史数组拆为可渲染的消息/事件模型。
- 支持加载中、空会话、错误、刷新和切换状态。
- 能读取长会话的分页或增量内容；若服务端暂不支持，至少提供明确的限制提示。
- 新建、切换和刷新 session 后，记录不会串线或重复。

## M3 Markdown 消息展示

### 交付结果

Codex 和用户消息中的 Markdown 能以安全、可读的方式展示，保留代码和结构化内容的可复制性。

### 范围

- 段落、标题、列表、引用、链接、粗体、斜体。
- fenced code block、语言标识、复制代码。
- 表格和基础换行处理。
- 不执行未经允许的脚本，不直接信任消息中的 HTML。

### 验收条件

- Markdown 不再以未格式化纯文本显示。
- 代码块、长行和表格在侧栏内可读，不破坏布局。
- 外部链接经过明确的打开行为处理。
- 恶意 HTML 和脚本不会在 Webview 中执行。
- 关键渲染样例具备自动化或人工回归用例。

## M4 模型与推理设置

### 交付结果

用户可以在发送前选择可用模型和推理强度，并能理解设置作用于默认值、当前 session 还是当前 turn。

### 推荐方案

- 全局默认设置：新 session 和新 turn 使用。
- Session 覆盖：只影响当前 Codex 会话。
- Turn 级参数：仅在 App Server 明确支持且有必要时提供。

### 任务

1. 通过 App Server 能力探针确认模型枚举、推理强度字段、默认值和错误返回。
2. 设计 Composer 工具栏或设置面板，避免把高频输入框挤成复杂表单。
3. 保存用户选择，但不保存凭据；提供恢复默认值操作。
4. 当模型或推理参数不被当前 CLI 支持时，显示兼容性提示并回退到默认行为。

### 验收条件

- 模型和推理强度选择会准确进入对应的 turn 请求。
- 新旧 session 切换不会错误继承不应继承的设置。
- 不支持的参数不会导致整个会话不可用。
- 设置可通过测试和日志确认实际生效。

## M5 审批 UI

### 交付结果

Codex 请求执行命令、修改文件或其他需要批准的操作时，用户能看到请求内容并作出明确决定；扩展不再静默自动拒绝。

### 推荐交互

- 审批卡片显示操作类型、摘要、工作区范围和风险提示。
- 操作按钮使用“批准一次”“拒绝”“取消/稍后处理”等明确状态。
- 默认最小权限，长期批准单独呈现并要求用户确认。
- 审批期间消息流保持可见，用户可以知道 Codex 正在等待什么。

### 任务与验收

- 将 App Server server request 从自动拒绝改为可等待的请求状态。
- 支持至少命令执行和文件修改两类审批事件。
- 处理超时、重复请求、会话切换和扩展关闭。
- 审批决定能正确回传服务端，并在消息时间线留下结果。
- 没有审批 UI 时继续保持拒绝策略；M5 完成后才切换默认行为。

## M6 Agent 工作流可视化

### 交付结果

用户可以理解 Codex 正在调用什么工具、执行什么命令、修改哪些文件，并能中断或继续工作流。

### 范围

- 工具调用和命令执行状态。
- 标准输出、错误输出和折叠详情。
- 文件变更摘要、差异入口和结果状态。
- turn 取消、重新发送、继续对话和必要的 steer 行为。

### 主要依赖

- M2 的统一事件时间线。
- M5 的审批状态机。
- App Server 对通知、取消和 steer 的实际支持。

## M7 上下文扩展与产品化

### 交付结果

上下文入口成为产品主流程，而不是单一的编辑器快捷方式；插件具备持续使用和发布所需的可靠性。

### 候选能力

- 多选区、当前文件、文件夹、搜索结果、诊断、终端输出、Git diff、符号和测试失败信息。
- 上下文项折叠、预览、去重、排序、大小提示和失效刷新。
- 工作区级默认设置、快捷键、命令面板入口和可访问性。
- App Server 断线重连、超时恢复、分页、日志诊断和性能控制。
- VSIX 打包、安装验收、版本说明和发布前检查。

## 跨里程碑质量门槛

- 每个里程碑都有自动化检查和可复现的 Extension Host 人工验收步骤。
- 协议能力先通过只读探针或固定 fixture 验证，再进入 UI 实现。
- Webview 输入、Markdown 和上下文内容均按不可信文本处理。
- 不把登录凭据、桌面应用私有数据或本机绝对路径写入仓库。
- 每完成一个里程碑形成独立、可回退的 Git 提交。

## 当前下一步

main 分支已完成 M1 的 inline `fileRange` Composer 原型。本分支将产品收敛为轻量上下文引用工具：先交付选区、文件和目录引用复制，再根据实际使用反馈决定是否恢复会话能力；模型设置、审批 UI 和 Markdown 展示继续保持为非本分支目标。

## 待确认事项

- App Server 当前版本是否支持结构化文件引用，还是需要扩展自行序列化为提示文本。
- 内嵌选中文本的默认上限、截断提示和是否按字符或 token 估算。
- 模型/推理设置是全局默认、session 覆盖还是 turn 覆盖的最终组合。
- “长期批准”是否进入首版审批 UI，还是只实现单次批准和拒绝。
